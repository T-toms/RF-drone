# B1 (a) 组核查：高 AUC 来自接收机还是来自内容（2026-11-10，claude-c3）

脚本 `check_a.py`（只读特征缓存与 IQ 缓存，CPU，anaconda python）。产物：`session_medians.csv`、`auc_a_by_content.csv`、`psd_summary.csv`、`drone_A_vs_B_matched_snr_auc.csv`、`drone_snr_bin_counts.csv`、`auc_bgA_vs_v3quiet.csv`、图16a/b/c。

## 结论
**B1 的 (a) 组没有检验到接收机差异，测到的是"两边内容不同"。** 所以按 (a) 打出的"接收机指纹"标签不能成立，"可疑""未见来源线索"也一样，都要作废。

## 证据
1. **bgA 是理想白高斯噪声**，61 个源录制逐一如此：shape_factor 中位数 1.1284（复高斯理论值 √(4/π)=1.1284），c42n 0.0004，谱平坦度 0.9988，duty 0，片段内功率/底噪 0.08 dB（session_medians.csv）。原因在构造方式：bgA 取的是 ISM 频段外 2345–2395 MHz 的镜像（任务 I），那里本来就没有发射源。
2. **v3 07-10"实验室背景"里有大量信号。** 08:48–08:54 的 5 个会话有强突发和宽带块，功率/底噪 7–21 dB；11:43–11:47 的 8 个会话有约 20 MHz 宽的弱 WiFi 块，位置在 2412/2437/2447 附近，高出底噪 1–3 dB，另有窄突发（图16a）。全部 260 片的中位数：shape 2.36，功率/底噪 15.5 dB，谱平坦度 0.11。**说它"几乎没有 WiFi"是错的。**
3. **两台接收机的平均功率谱形状一致**：通带滚降位置、截频边沿和陷波都相同。v3 多出来的只有 ±3 dB 起伏和 WiFi 信道处的鼓包（图16b）。所以谱平坦度 AUC=1.000 来自内容，不是接收机硬件。
4. **v3 里只取 duty=0 的 57 片**（没检出突发），c40/c41/occ/duty/n_bursts/c20 的 AUC 降到 0.50–0.54。shape、c42n、gamma_max、谱平坦度仍有 0.96–1.00，但这些片段的功率/底噪中位数是 1.13 dB，bgA 是 0.08 dB，说明还残留着弱 WiFi（auc_a_by_content.csv）。
5. **内容相同的纯底噪对照**：v3 背景里功率/底噪 < 0.5 dB 的片段只有 4 片，全部来自 07-15 一个会话，样本太少，只能参考。结果是：shape 0.76，c42n 0.67，kurt 0.55，c20n 0.57，duty/occ/n_bursts 0.50；sigma_f 1.000（0.2306 对 0.2319），谱平坦度 0.92（0.9982 对 0.9988），gamma_max 0.89。sigma_f 和谱平坦度在绝对值上只差 0.1–0.5%，可能是带内噪声谱形的细微差别。但只有 1 个会话、4 片，分不清是接收机还是会话造成的（auc_bgA_vs_v3quiet.csv）。

## 第 2 点（包络特征 ≈ 片段内信噪比）
- 图16c：功率归一化后，shape_factor、c42n、谱平坦度仍随"片段内平均功率/底噪"变化。五组点（A/B 的无人机和背景）落在同一片点云上，bgA 全部挤在 (0 dB, 白噪声值) 这一个点。
- 只比无人机，A（data）对 B（v3）：合并后各特征 AUC 0.51–0.60；按片段内信噪比分箱后，多数在 0.5–0.7（drone_A_vs_B_matched_snr_auc.csv）。在信噪比相近的无人机之间，这些特征分辨接收机的能力有限。
- 所以 B1 里"2.4G 接收机 A 标签 AUC=1.000"其实是"任何信号对纯噪声"，任务本身太简单，不能说明特征能区分无人机和真实背景。

## 对做法 B 的影响
- 来源检查需要重新设计：(a) 组两边的内容必须可比。
- 真正的风险不在接收机硬件指纹，而在训练数据的构成：A 侧背景全是纯噪声，A 侧正样本全是强信号。特征分支很容易学成"有没有信号"，碰到 WiFi 这类真实背景就会虚警。这与主线已知的问题是同一个。
