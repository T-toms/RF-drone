## 3. 时频图（预先算好缓存，全部样本同一套参数）

每个片段 → 一张 256×256 float16：
1. `torch.stft`：n_fft = 1024，hop = 512，Hann 窗，`center=False`，`onesided=False`，`return_complex=True`；功率 `|X|²`，`fftshift` 使频率轴从低到高。全 1024 bin 覆盖的是 fs 跨度（2.4GHz 2399.28–2460.72 MHz，5.8GHz 5750–5850 MHz），**只保留落在通带 2405–2455 / 5755–5845 MHz 内的 bin**（约 833 / 922 bin），过渡带与阻带不进入输入。（2026-11-08 Codex 指出原文把全 FFT 标成通带，已更正。）2.4GHz 得到 2399 帧，5.8GHz 3905 帧。
2. **在功率域**用 `F.adaptive_avg_pool2d` 平均池化到 (256 频, 256 时)（频率约 3.3 / 3.6 bin 合 1；时间约 9.4 / 15.3 帧合 1）。不要在 dB 域池化、不要用双线性插值（会把短脉冲丢掉）。
3. 转 dB：`10·log10(P + eps)`，eps = 该样本功率中位数 × 1e-3（让陷波凹坑最深约 −30 dB，不出现极端负值）。
4. 每个样本自己标准化：减自身均值、除自身标准差。
5. 缓存为 `<band>_<split>_spec.npy`（N×256×256 float16）+ 同名 `_meta.csv`（索引行原样 + 缓存序号）。GPU 上算，按块顺序读 IQ。

缓存建好后，随机抽 2.4GHz 与 5.8GHz 各 6 张（data 无人机、v3 无人机、v3 背景各 2）画成 `fig0_input_examples_<band>.png`，横轴 ms、纵轴 MHz（真实频率），标陷波频点。自己打开看：信号位置对、频率方向没有翻转、背景里只有 WiFi/底噪。有问题先修再继续。

## 4. 训练（每个频段 × 每个种子）

- 类别不平衡（2.4GHz train 无人机约 2984 片 vs 背景 234 片；5.8GHz 约 1971 vs 194）：交叉熵用**类别权重 = 训练集频率倒数并归一化到均值 1**。不做重采样。
- 优化：AdamW，lr 1e-3，weight_decay 1e-4，cosine 退火到 1e-5，**40 epoch**，batch 64，AMP（bf16 或 fp16 自动选）。
- 每 epoch 在 val 上算：背景虚警率 FA（背景被判无人机的比例）、无人机漏检率 Miss（按 argmax）、loss、balanced accuracy。**选模型 = val 上 (FA + Miss) 最小的 epoch**，并列取 loss 低者。保存 best 与 last 的 checkpoint。
- 另外在 val 上确定一个阈值 `thr_fa1`：无人机类 softmax 概率的阈值，使 val 背景 FA ≤ 1%（若 val 背景数不够则取能达到的最严格阈值，写明背景片数）。test 同时报告 argmax 与 `thr_fa1` 两套结果。
- 固定随机种子（python/numpy/torch）；记录每个 epoch 的指标到 `train_log_<band>_seed<seed>.csv`；画 `fig5_curves_<band>.png`（3 个种子的 val FA、Miss、loss 曲线）。
- 预计每次训练几分钟；若单次 > 30 分钟检查是不是数据加载瓶颈（缓存应全载入内存，2.4GHz train 约 0.4 GB）。

## 5. 评估（test，每个频段，3 个种子分别报告 + 均值±标准差）

### 5.1 主指标
- 背景 FA、无人机 Miss（argmax 与 thr_fa1 两套）。
- 无人机 Miss **按 (dataset, model, state, bw_label)** 分表；背景 FA 按 v3 会话（group_id 的日期/环境：07-09 urban、07-10 lab、07-11 home、noise_adrv 等）分表。
- 明确写出 test 背景片数（2.4GHz 80、5.8GHz 60）及"0 错时的 95% 上界 ≈ 3/N"，说明 ≤1% FA 在此样本量下**不可验证**，只写事实。

### 5.2 按来源的召回率（检验 1）
- 同一模型、同一阈值下：data/ 无人机 recall vs v3 无人机 recall。
- **同型号对比**（用户要求只比同机型）：Mini 5 Pro —— data `mini5 pro`（code 007；两个频段都有）vs v3 `mini5pro`；EVO II Pro V3 —— data `evo ii pro v3`（011，只有 2.4GHz）vs v3 `evo2pro_v3`。按频段、按 bw_label 列出各自 test 片数与 recall。
- 同时列出每个 test 片段的"信号强度代理"：该片段 1 ms 单元功率的 90 分位数 − 10 分位数（dB，在截取后 IQ 上算），按来源画分布（`fig2_recall_by_source_<band>.png`：左图按来源/型号的 recall 柱状，右图信号强度代理的直方图按来源着色）。目的是让读者能判断 recall 差异是来源造成的还是信号强度造成的。

### 5.3 叠加检验（检验 2，最重要）
把 **data/ test 无人机片段的 IQ**（接收机 A）叠加到 **v3 test 背景片段的 IQ**（接收机 B）上，再用训练好的模型判别：
- 对每个 data/ test 无人机片段 d 和循环取用的 v3 test 背景片段 b：`mix = b + g·d`，g 使 `10·log10(g²·mean|d|² / mean|b|²) = X`，X ∈ {−10, −5, 0, 5, 10, 15, 20} dB。按同一套 §3 流程算时频图后推理。
- 三组对照，同样的 X 集合：
  (a) **data 无人机 + v3 背景**（主检验）；
  (b) **v3 无人机 + v3 背景**（同接收机对照；v3 test 无人机片段）；
  (c) **v3 背景 + 另一个 v3 背景**（叠加操作本身是否造成虚警；标签仍是背景，报告 FA）。
- 每组每个 X 报告检出率（argmax 与 thr_fa1），3 个种子分别算再取均值±标准差。画 `fig3_mix_test_<band>.png`：横轴 X，纵轴检出率，(a)(b) 两条曲线 + (c) 的 FA 曲线。
- 再画 4 个叠加样本的时频图 `fig3b_mix_examples_<band>.png`（X = −5、5、15 和原始 b），让读者看到叠加后信号确实在。
- 说明：mean|d|² 包含接收机 A 自己的底噪；在 X ≤ 10 dB 时接收机 A 的底噪比 b 的底噪低得多，可忽略；在报告里给出 data/ 片段"信号功率 / 底噪功率"的典型值（用 §5.2 的代理）以便读者判断。

### 5.4 Grad-CAM（检验 3）
- 对 best 模型（seed 2026），在 `layer4` 输出做 Grad-CAM（目标类 = 预测类），每个频段取 test 中 data 无人机、v3 无人机、v3 背景各 6 张（含判对与判错的若干），画 `fig4_gradcam_<band>.png`：左时频图（真实 MHz/ms 轴，叠加该录制的占用子带边界虚线，背景无子带），右热力图叠加。
- 另算**类别平均热力图**（每类所有 test 样本平均）`fig4b_gradcam_mean_<band>.png`，并给出一个数字：热力图落在"占用子带内"的能量占比（无人机样本；背景样本给出落在 WiFi 频段 2412±11 / 2437±11 MHz 内的占比）。
