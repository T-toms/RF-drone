# 一阶段损失归一化对照（STAGE1-LOSS-NORM）

> 状态：**已完成的开发对照**。正式候选训练 1 次（seed 2027，5 epoch）已完成并通过三路核验。
> 本任务只新增这一份候选训练，未追加 seed、未扩大轮数、未调门限、未换采样器、未改 BN/学习率/噪声档/数据划分。
> 旧 seed2026 / seed2027 运行目录与冻结输入全程只读（前后哈希快照一致，见 5.5）。

## 1. 任务与假设

背景：12 机型 + 背景的一阶段（背景 vs 无人机）协议在冻结划分上跑过两个训练种子，
seed2026 四条件平均 pooled BA = 0.900137，seed2027 = 0.799845，相差 −10.03 pp。
`work/stage1-batch-balance-diagnostic-20260927.json` 用两个种子十轮的落盘顺序哈希复现出：
batch=4 时约 77% 的批次完全不含背景窗，默认 weighted CE 在批内归一化，
使“全局类别权重”在小批次上的预期作用被削弱。

本任务只检验一个明确假设：

> 在 batch=4、训练集 9590 窗（背景 600、无人机 8990）的条件下，
> 把损失从“按批内权重和归一化”改成“按**实际批大小 × 全局训练均值权重**归一化”，
> 是否改变按冻结规则选出的四条件平均 pooled BA。

该证据**不能**证明种子差异的因果来源，也**不能**证明跨种子稳定性；本次只做一次配对对照。

## 2. 数学接口

训练计数 N = 9590，n₀ = 600，n₁ = 8990，权重 w_c = N / (2·n_c)（仅用 train 计数）。
对每个窗口 i（标签 y_i，交叉熵 CE_i）：

| 模式 | 公式 | 分母规则 |
| --- | --- | --- |
| `batch_weight_sum`（默认、历史行为） | `L = Σ_i(w_yi·CE_i) / Σ_i(w_yi)` | 本批出现的权重之和；与 `torch.nn.CrossEntropyLoss(weight=...)` 的 `reduction='mean'` 完全一致 |
| `global_train_mean`（候选） | `L = Σ_i(w_yi·CE_i) / (B_actual · μ_train)` | `B_actual` 是本批**实际**窗口数；`μ_train = Σ_c(n_c·w_c)/N` |

- 本任务实际记录：`class_weights = [7.991666793823242, 0.5333704352378845]`，
  `μ_train = 1.0000000301441634`（构造上为 1；float32 下 `4·μ_train → 4.0`、`2·μ_train → 2.0`）。
- 9590 = 2397×4 + 2，因此每个 epoch 的最后一批只有 **2** 个窗口；
  候选模式该批分母实测为 **2.0**，不是 4.0（5 个 epoch 各一次，位置 2397/4795/7193/9591/11989）。
- 验证损失定义保持不变，仍是原始 weighted CE；候选目标在验证集上的数值另存
  `validation_objective_loss.json`，两者不可混名比较。

机制：默认模式在纯无人机批次上把无人机权重整体约掉（每窗有效权重 0.25），
而 1 背景 + 3 无人机的批次里背景窗占该批梯度 7.9917/9.5918 ≈ 83%；
候选模式给每窗固定 w_c/(B·μ)，背景窗在混合批中的相对权重提高约 2.4 倍、
纯无人机批的整体尺度下降约 1.9 倍——即恢复全局类别权重，同时改变逐批梯度尺度。
本次独立复算的批组成（5 个 epoch 的冻结顺序、2398 批/epoch）：
**77.06%–77.86% 的 batch 完全不含背景窗**，与诊断一致（均值 77.43%）。

对旧训练入口的最小改动（全部默认关闭，默认路径逐行不变）：
`train_stage1()` 新增 keyword-only 参数 `train_criterion` / `eval_criterion`（训练目标与"被记录的验证损失"
分离）、`extra_config`（附加 run_config 字段，键冲突即拒绝）、`epoch_callback`（每个 epoch 结束后的
纯观测钩子，用于落盘恢复状态）、`start_epoch` / `initial_state` / `resume_record`（epoch 边界恢复），
并新增 `rng_state_payload` / `restore_rng_state` / `resume_identity_errors` / `apply_training_state` 四个工具函数。
默认不传这些参数时执行的就是已验收 seed2026/seed2027 的同一代码路径。

默认模式 `batch_weight_sum` **直接返回原始 `nn.CrossEntropyLoss(weight=...)` 模块**，不经过本任务新写的算术；
新写法只用于候选模式，其与原始模块的差异实测 ≤1e-6（float32 末位量级，源于 PyTorch 在 C++ 内核里做 `Σ(w·CE)/Σ(w)`）。

### 3.2 可恢复性

- 每个 epoch 结束原子写 `last_training_state.pt`（模型、前端、optimizer、GradScaler、
  Python/NumPy/torch-CPU/torch-CUDA RNG、已完成 epoch、下一 epoch、历史与当前最佳选择、协议/代码/索引身份）；
  本次 5 次写入均成功（134,204,307 → 134,207,187 字节，`last_training_state.json` 记录每次 SHA256）。
- `--resume-from` 只在 epoch 边界恢复：先校验 schema、索引/划分哈希、种子、epoch 数、损失模式与协议**内容**哈希
  （`protocol_core_sha256`，刻意排除 `created_at`，否则恢复段无法与中断段匹配），再恢复模块与 RNG。
  代码身份经协议内容哈希**传递固定**：`protocol.json` 的 `code_sha256` 覆盖 7 个源文件，
  其任何改动都会改变 `protocol_core_sha256`，从而使恢复被拒绝。
  不宣称支持任意批次或断电时精确续训。
- 恢复段落的读取审计只覆盖本进程的 epoch，并在 `loader_read_audit.json` 写明 `resumed_epochs`
  与只属于本段的 `expected_train_windows`，不伪造无中断预算。

## 6. 限制与不能声称的结论

- 这是**一次**训练种子（2027）的配对对照，只给出一次配对效应估计，
  **不能**声称跨种子稳定性；seed2026 只说明“换一个种子可能落在什么位置”，不是损失改动效应。
- 验证集 16 个源文件与训练源文件处于同一采集时间簇（同批次文件级划分），
  因此全部数字都是**开发评估**：不是未参与选型的独立最终测试，也不是跨会话、跨接收机、跨环境泛化证据。
- 门限固定为 margin>0，未做任何门限扫描；报告的是该操作点上的 BA/FPR/FNR 取舍。
  描述性 AUC 只说明可分性，不能当作已调优结果，也不能与固定门限的 BA 混为一谈。
- 候选在 pooled BA 上更好，但**在原始准确率与描述性 AUC 上并不更好**（−10/−12/−15 dB 准确率更低），
  且 12 个机型的逐类召回全部下降；这不是“检测器整体变强”，而是操作点向背景侧移动。
  选择哪一个操作点取决于应用对虚警与漏检的相对代价，本任务不做该决策。
- 两种训练目标的损失数值定义不同（分母不同），**不可**直接比较大小。
- 本任务不训练第二阶段、不做串联评价，因此不产生 12 机型识别率结论。
- 单机单卡、无重复运行；GPU 侧未承诺逐位可复现（恢复确定性是在同一设备的确定性模式下比对的）。
- 读取审计证明测试 MAT 的 IQ 未被打开；它不证明这些文件从未被本项目其它历史使用。
- 小瑕疵记录：`objective_loss.json` 的 `expected_tail_denominator` 字段写的是 float64 值
  2.0000000603（运行开始前生成的代码版本），而真正的分母在 float32 下是 2.0；
  逐步 CSV 与核验都以 2.0 为准，该字段仅作文档说明。
