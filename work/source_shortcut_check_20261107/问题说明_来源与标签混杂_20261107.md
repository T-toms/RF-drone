## 〇、更正（2026-11-11）

### 〇-1　"模型会靠认接收机/认环境拿分"——只对了一半：2.4G 靠的是环境无线网，5.8G 没有看到依赖来源

**原来的说法**（第二节、第四节末尾）：模型只要学会认接收机或认环境就能拿高分，部署时会失效；第四节的逻辑回归证明了"能走捷径"，"会不会走"要训练后看。

**后来做了什么**：第一轮训练（任务 H，时频图输入，2026-11-08）之后，做了"背景替换"对照。同一批无人机样本、同样的功率比，一份叠到白噪声上，一份叠到城区背景上，看模型检出率差多少（[图10](../review_taskH_20261108/图10_背景替换对照.png)，3 次训练平均）：
- **5.8G**：两种背景下检出率几乎一样，例如实验室无人机在 0 dB 时 100% 对 98%。纯白噪声 3 次训练都判 0% 无人机。另外又测了陷波后的白噪声，以及按两台接收机各自底噪形状合成的噪声，3 次训练也全部 0/200 判无人机（任务 K，[图13](../side_5p8_controls_20261109/图13_空频段与底噪代理对照.png)）。**模型没有表现出依赖接收机或来源。**第三节第 26–30 行的"接收机指纹"在数据里确实存在，但模型没有用它。
- **2.4G**：同一批实验室无人机，在 0 dB 时叠白噪声检出 90%，叠城区背景只检出 57%。城区无人机原样检出 58%，叠上白噪声（功率比 −10 到 5 dB）反而升到 79%–88%：白噪声把画面上的无线网纹理盖住了，模型就更容易判成无人机。说明 **2.4G 模型把"画面上有无线网"当成了"没有无人机"的证据**。原因是训练集里有无线网的样本几乎全是背景：实验室录的无人机都没有无线网，城区录的无人机只有 152 段。
- 所以老师说得对：**模型主要靠的是信号本身**。原文"接收机底噪捷径"的说法不成立。2.4G 真正的问题是环境无线网和标签混在一起，不是接收机硬件。

**后来怎么解决的**（只在 2.4G 上做，每次只改一件事，每组 3 次训练）：
1. 加入实验室接收机的背景（任务 J，[图12](../train_stage1_L20_bgA_20261109/图12_加入接收机A背景前后_2.4GHz.png)）。实验室录不了纯背景，所以从实验室接收机录音里取 ISM 频段外、几乎没有发射源的 2342.6–2393.5 MHz，镜像到 2405–2455 MHz 作为替身（任务 I）。
   - 第一轮模型在这批背景上误报 100%。原因是这批背景里没有任何信号，陷波留下的三道窄凹坑经标准化后被放大，模型把它当成了线索；**不是接收机指纹**。对照：白噪声做同样的陷波，3 次训练也 100% 判无人机；把凹坑抹平后，其中两次训练在这批背景上的误报降到 0% 和 1.5%。
   - 加入这批背景训练后，它的误报从 100% 降到 0%。
2. 合成"无人机 + 无线网"样本（任务 L，[图14](../side_L_wifimix_20261110/图14_叠加WiFi训练前后_2.4GHz.png)）。训练集里，把实验室无人机信号直接加到城区背景信号上，标成无人机。同时把实验室背景也加到城区背景上，标成背景，这是 Glüge 等 2024 年论文的做法（读的是全文）。
   - 城区无人机认出率从 62% 升到 81%。最难的 mavic2 从 20% 升到 53%，mini3pro 从 21% 升到 77%。
   - 只叠无人机、不叠背景时，"实验室背景 + 城区背景"的误报会升到 24%，即出现新捷径；两类都叠时降到 1.9%。
3. 修补陷波凹坑（任务 M，[图15](../side_M_notchfill_20261110/图15_陷波修补前后_2.4GHz.png)，修补前后时频图对比见[图15b](../review_20261109/图15b_陷波修补前后_时频图对比_2.4GHz.png)）。生成时频图时，三处凹坑用坑外紧邻的对称位置填平。
   - 纯白噪声误报从 5% 降到 0%，其他指标没有可靠变化。
   - 城区无人机认出率 86%，3 次训练之间相差约 ±9 个百分点。

**目前仍存在的问题**：
- 城区背景测试只有 80 段，误报 2.5%，"≤1%"验证不了。
- mavic2 认出率只有约 57%。
- 模型对空白画面里的细暗线仍然非常敏感：把修补后的凹坑人为压回原深度，3 次训练里有 2 次几乎全判成无人机。因此部署时必须使用同样的陷波和修补方法。
- 5.8G 没有实验室接收机的背景，部署接收机在 5.8G 上的误报只能用代理噪声估计（任务 K），没有真实背景可测。

## 一、前因：两批数据是怎么拼在一起的

第一阶段要训练"有没有无人机"的二分类，需要两类样本：

| 来源 | 接收机 | 采集时间/地点 | 有无人机 | 有背景 |
|---|---|---|---|---|
| `data/` | 接收机 A（122.88 MS/s） | 2026-09 实验室 | ✔ | **✘ 一条都没有** |
| `datasets_v3` | 接收机 B（ADRV9009，重采样到 100 MS/s） | 2026-07 城区/实验室/家 | ✔（**全部** 07-09 城区，增益 25 dB） | ✔ |

所以（图1）：
- 背景 **100%** 来自接收机 B；无人机样本 **93%（2.4G）/ 89%（5.8G）** 来自接收机 A。
- 背景 : 无人机 = **1 : 13.8（2.4G）**，**1 : 12.2（5.8G）**。背景总共只有 8.8 s / 7.0 s。
- raw/ 原始 .bin 每段只有 0.12 s，v3 已经用了其中 0.1 s，回到 raw/ 最多只能多拿 ~20% 背景，解决不了数量问题。

## 二、问题是什么（一句话）

在这份训练集里，"是哪台接收机/哪个环境录的"和"标签"几乎一一对应。模型不需要学会认无人机信号，**只要学会认接收机/环境就能拿高分**；而测试集也是同样的构成，所以**测试分数高也无法证明模型学会了认无人机**。真实部署时只有一台接收机，这条捷径不存在，模型就会失效。【已更正，见〇-1：训练后的对照显示模型主要靠信号；2.4G 的问题是环境无线网，5.8G 没有看到依赖来源】

## 三、证据：两台接收机/两种环境在数据里确实看得出来

**5.8G —— 接收机指纹（图4）**
每条录音取"每个频点在整条录音中功率的第 10 百分位"作为底噪，再减去自身中位数得到形状。
- 接收机 B 的无人机录音（22 条）和背景录音（16 条，城区/实验室/家三个场景）形状**完全重合**：频段两端各下垂 0.6–0.7 dB。
- 接收机 A（39 条）是另一种形状：整体一条斜线，右端不下垂。
- 结论：这是接收机（及 v3 的重采样滤波）本身的特征，与有没有无人机无关。【补充，见〇-1：这个差别在数据里存在，但训练后的 5.8G 模型没有表现出依赖它】

**2.4G —— 环境 WiFi（图2、图3）**
- 没有持续 WiFi 时（接收机 B 的实验室录音 07-10 / 07-16 / noise_adrv vs 接收机 A；noise_adrv 不是纯接收机自噪声，时频图里有强信号，见图7），两台接收机底噪在绝大部分频段相差 < 0.4 dB（图3a）——2.4G 接收机本身差别不大。【已更正，见〇-2：07-10 的录音其实含弱无线网和强突发，不能当无无线网对照；结论改由图17 支持】
- 城区和家里的录音在 2412、2437 MHz 有两个 2–4 dB 的鼓包，中间有凹口（图3b），这是 WiFi 1、6 信道的样子，且 90% 以上时间都存在（图2 中浅蓝的一层）。
- v3 的无人机**全部**在城区录 → 全部带这层 WiFi；`data/` 无人机全部没有。

**更正**：Task F 报告里我写"v3 底噪有 ±3 dB 起伏"，那张图（`floor_shape_2.4GHz.png`）的算法是把整类所有录音最安静的 10% 小格混在一起平均，在 2.4G 里混进了 WiFi。2.4G 的起伏是**环境 WiFi，不是接收机**；接收机指纹只在 5.8G 明显。

## 四、测试：一个完全看不到无人机信号的分类器能拿多少分（图5）

做法：每个 10 ms 训练片段只提取 3 个与无人机无关的数：
- 5.8G：左端下垂、右端下垂、右段坡度；
- 2.4G：WiFi 1 鼓包高度、WiFi 6 鼓包高度、左端底噪。

用 Task F 原划分，在训练集上训练逻辑回归（背景 vs 无人机），在测试集上评估（只用 keep=True 的片段，就是实际训练会用的样本）：

| | 背景误报 | data/ 无人机检出 | v3 无人机检出 |
|---|---|---|---|
| 2.4G | **0.0%**（180 片段） | **93.2%**（2094） | 0.9%（228） |
| 5.8G | 6.7%（135） | **90.2%**（1410） | 7.2%（279） |

对照（排除"特征里其实含无人机信息"的可能）：同样的特征，只在**同一接收机、同一地点、同一天**（v3 城区）里分背景/无人机，平衡准确率 2.4G 0.51、5.8G 0.63，接近瞎猜（0.5）。
→ 这几个特征本身认不出无人机，它在混合数据上拿到的"背景零误报 + data/ 无人机 93% 检出"，完全是靠认来源得到的。只有 v3 无人机这一小块（测试集的 9%/15%）暴露了它其实不会认无人机。

真正的 CNN 能看到全部 IQ，信息比这 3 个数多得多，**能否**走捷径已经被证明；**会不会**走、走多少，只能训练后看 data/ 无人机 vs v3 无人机的分来源指标。【已回答，见〇-1：第一轮训练 2.4G 实验室无人机认出 92%、城区 58%，5.8G 为 100% 和 86%；背景替换对照显示 2.4G 用了无线网线索，5.8G 没有】

## 六、需要老师决定的事

1. **能否请实验室用 `data/` 那台接收机、同一实验室、同样设置，再录一批"不开无人机"的背景？**（时长最好与无人机相当，每个频段至少几十秒，分多次录）这是唯一能从根本上消除混杂的办法。
2. 在新背景到位前，第一阶段是否先只用接收机 B（v3）做？但 v3 内部也有混杂（无人机全在城区、背景分散在三处，见对照 2.4G v3 内部 0.74）。最干净的子集是 **v3 城区**：无人机 2.4G 8.5 s / 5.8G 9.8 s，背景只有 2.25 s / 2.2 s。
3. 如果仍要混用 `data/`：评估时必须**按来源分开报告**（以 v3 无人机检出率、背景误报为准），并考虑对 5.8G 做接收机均衡（除去各接收机的底噪形状）；但均衡解决不了 2.4G 的环境 WiFi 差别。
