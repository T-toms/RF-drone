# FULL-ARCHIVE1：新 F 盘下载完整 DroneRFa 压缩包

## 用户目标与边界

用户确认原 F 盘现为 G 盘，新 F 盘有约 1.8 TiB 可用。用户要求将 DroneRFa 完整数据集放到新 F 盘，并在新 F 盘全量数据验证完成后，删除 G 盘以前下载的数据。用户指出旧逐 MAT 小 RAR 下载慢且故障多，要求改为直接下载官方完整压缩包。

本任务先实现并启动稳定的**完整 RAR 下载**，不是旧 `download_heldout_files.py` 的逐文件下载。G 盘旧数据在本任务中只读、绝不删除。全量下载完成后的解压、验证和 G 盘清理另设严格验收阶段。

## 已核对事实

- 官方 URL 固定：`https://china.scidb.cn/download?fileId=c403fc76444e4b9989e4f3ff570f3b3d`
- 项目 `dronerfa_manifest.json`：RAR 大小 `615955805466` 字节（573.65 GiB），ETag `"6774350c-8f69d3b51a"`；索引共 632 项，包括 630 个 MAT、1 个 PDF、1 个目录项。
- 全部解压后总字节：`641798228425`（597.72 GiB）。RAR + 解压共 `1257754033891` 字节，当前新 F 盘约有 `1937472172032` 字节可用，理论剩余约 633 GiB。
- 新 F 盘根目录目前没有 `DroneRFa数据集`。G 盘 `G:\DroneRFa数据集\original` 有 62 个 MAT（约58.85 GiB），另有旧下载记录与断点；原下载器 PID 6376 已停止。
- 旧日志约 0.9–1 MiB/s，完整 RAR 在同速下需约 7 天。这只是旧速度，不代表新方案实测速度。

## 实现要求

1. 先核对项目工作流状态，无活动 DSH 任务时才开始。保存新的冻结配置，包括 URL、RAR 期望大小、ETag、索引 SHA256、F 盘目标路径、卷标记 UUID、G 盘旧数据路径与待清理范围。不得打印或保存认证 Token。
2. 新下载器使用**同一个官方完整 RAR 的直接 HTTP 下载**。可以用 `curl.exe -L -C -` 的续传方式，也可以用独立的连续 Range 下载实现，但不能调用旧逐 MAT 小 RAR 选择脚本。无论哪种方式，必须在继续写入前验证服务端返回的 Range/Content-Range、总大小和 ETag，防止断点后拼接错误内容。遇到 DNS/短暂网络错误可有限退避重试；协议或远端文件身份变化立即停止。
3. 按真实下载字节做有界测速（建议 128–256 MiB 或最多 3 分钟），测速字节直接留在同一个 `.part` 断点里，不重复浪费下载。记录实际 MiB/s，并与旧日志的约 1 MiB/s 作审慎比较：不能声称方法本身必然加速。
4. 下载器要可安全重复运行：匹配身份时续传，同一时间只允许一个下载进程；完成时严格核对总字节 `615955805466`，再将 `.part` 原子重命名为 `.rar`。不同身份、超预期大小、未验证 HTTP 206 立即停止。
5. 每写入一个完整块后持久化断点状态。不能在 F 盘保留完整压缩包以外的巨大第二副本。日志记录开始时间、远端身份、最新下载字节、速率、重试原因。
6. 开始前重查新 F 盘可用空间至少能容纳剩余压缩包 + 完整解压估计 + 20 GiB。中途空间不足时停止，保留合法断点。
7. 通过适当测试验证：Range 不符合预期时拒绝、已有合法断点续传、超长/短响应拒绝、锁防止第二进程、卷标记变化拒绝。测试不需要下载完整数据。
8. 用现有 DSH Desktop 会话可见地实施。启动真实长期下载进程，后台进程要独立于 DSH 的任务轮次继续运行；Windows `Start-Process` 加 `-WindowStyle Hidden`。若沙箱限制导致子进程初始化失败，只对已授权的这个固定命令申请提升，不改权限设置。启动后至少观测两次 `.part` 增长、日志无协议错误、PID 有效。
9. 交接 `completed` 只代表“下载器实现、测速和长期进程启动已验收”，必须明确当前实际已下载字节，不能宣称完整数据集已到位。
