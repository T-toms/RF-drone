# Air 2S 逐窗口漏检分析

本分析只读取已有验证集推理分数，没有重新推理、训练模型、改门槛或使用测试集。源文件：`C:\Users\Administrator\Desktop\数据集处理\dronerfa_baseline\outputs\validation_diagnosis_20260917_161707\validation_scores.csv`。

## 结论

Air 2S 在 −12 dB 检出 137/150 个窗口，在 −15 dB 检出 49/150 个窗口。按 `file_path + start` 配对后：

- −12 dB 和 −15 dB 都检出：49 个；
- −12 dB 检出、−15 dB 新增漏检：88 个；
- −12 dB 漏检、−15 dB 恢复检出：0 个；
- 两档都漏检：13 个。

同窗配对确认：净增的 88 个漏检全部来自原先检出的窗口，没有反向恢复窗口。

新增漏检贯穿整段 1.5 s 录制，并非只由一个局部坏片段造成。六个 0.25 s 分段的新增漏检比例为 40%–72%；最严重的是 1.25–1.50 s，为 18/25 个窗口。最长连续新增漏检区间为 1.07–1.15 s，共 8 个连续 10 ms 窗口。−15 dB 下全部漏检的最长连续区间为 1.36–1.50 s，共 14 个窗口。

在 −12 dB 时，随后仍能在 −15 dB 检出的窗口，其 margin 中位数为 8.5391；随后新增漏检窗口为 4.3877。这说明 −12 dB 时较低的余量与 −15 dB 失效有关，但这里只是同一录制上的关联。

## 如何理解

这些结果把问题定位到了同一份 Air 2S 验证录制中的具体时间区间。它支持下一步从代表性稳定窗口和新增漏检窗口中抽取原始 IQ/时频图进行对比，而不是先盲目换网络。

当前不能把差异直接解释为“Air 2S 机型本身更难”。验证集中 Air 2S 只有一份源录制，机型和本次采集条件绑定。噪声是对逐窗 RMS 归一化后的 IQ 附加 AWGN，数值也不是现场绝对信噪比。旧训练范围到 −12 dB，且旧模型按 clean 验证表现选出；这两个因素仍需用固定对照实验检验。
