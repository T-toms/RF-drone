## 2. 方法

### 2.1 预注册（联网之前完成）

`calibrate_htime_rules.py` 先在**已有的 14 个本地成员**上锁定解码规则，写入 `htime-decode-preregistration-20260925.json`：

- 样本：`DroneRFa_pilot.rar` 12 个成员 + G 盘两个遗留 `.part` 归档头各 1 个成员 = 14。
- 规则在跑之前写死，联网时只允许执行同一份代码（`rar5_header.py` 的 SHA256 被同时记进预注册文件与联网运行的前置闸门）：

| 规则 | 内容 |
|---|---|
| `HDR-1` | `HEAD_CRC` = CRC32( `blob[4 : 4+len(HEAD_SIZE vint)+HEAD_SIZE]` ) |
| `HDR-2` | `header_span = 4 + len(HEAD_SIZE vint) + HEAD_SIZE`；`block_offset` 处必须是 FILE 块（`HEAD_TYPE==2`） |
| `HTIME-1/2` | 取 extra 区 `FHEXTRA_HTIME`(type 3) 记录；优先取 flags 置 `0x02`(mtime) 的第一条，否则取第一条 |
| `HTIME-3` | 编码**只**由 `flags & 0x01` 决定：置位 → `data[1:5]` 为 uint32 Unix 秒；未置位 → `data[1:9]` 为 uint64 Windows FILETIME（epoch = 值/1e7 − 11644473600） |
| `HTIME-4` | 长度不足即报错，**不**尝试其它解释 |
| `HTIME-5` | 无 HTIME 记录时回退到 FILE 头 MTIME 字段（`FILE_FLAGS & 0x0002`），否则置空 |
| `TZ-1` | 存储值为 UTC；`file_mtime_proxy_local = 时刻 + 8 小时`（Asia/Shanghai），**永远如此，不允许逐候选调整** |
| `TZ-2` | `proxy_date` = 本地代理日期；`night_key` = (本地代理时间 − 6 小时) 的日期，与 META-SPLIT-1 一致 |
| `BUDGET-1` | 单成员头部 ≤128 字节，另加 8 字节重复前缀；绝不读取 `block_offset + header_span` 及之后的任何字节 |

**预注册校验结果**：14/14 块头 CRC 通过；14/14 的 RAR 时间与同文件 MATLAB `Created on` 在 2 秒内一致（残差 −2…−1 秒）；14/14 编码为 `windows_filetime_uint64`、`htime_flags=2`；最大头部跨度 71 字节。`preregistration_pass = true`。

### 2.2 两段式有界读取

对每个候选：

1. **阶段 1**：`Range: bytes=<off>-<off+7>`（8 字节）→ 解出 `HEAD_SIZE` vint，算 `header_span`。
2. **闸门**：`header_span > 128` 或块类型不是 FILE → 记为异常并**跳过**阶段 2，不扩大读取。
3. **阶段 2**：`Range: bytes=<off>-<off+header_span-1>` → 完整头部，**只到这里**。

客户端在**读取正文之前**先校验 `206`、`Content-Encoding`、`Content-Range` 精确区间与总长、`ETag`、`Content-Length`；任一项不符立刻关闭连接且**不读正文**，因此不可能退化成整包下载。

## 9. 三个必答问题

### 9.1 旧三类是否各有与现有 104 文件不同的文件日期候选？

**不是"各有"。只有 `T0000` 有。**

- 按"与本类现有 8 个文件的日期不同"算：`T0000` 是（2022-12-13），`T0010` 否（全在 2022-11-27），`T0101` 否（全在 2022-11-28）。
- 按"不在现有 104 文件的三个日期 {2022-11-27, 2022-11-28, 2023-02-27} 之内"算：同样只有 `T0000` 的 2022-12-13。
- 进一步地，`T0010`/`T0101` 的候选不仅是"同一天"，而是**与现有文件同属一段连续采集**（§8.2、§8.3）。所以对这两个类，归档里不存在任何"另一个文件日期的候选"。

### 9.2 候选是否可能支持"未参与选型的文件级测试"？

**机械上：是，而且只对 `T0000` 有实际意义。**

- 候选确实"未参与本项目选型"（§7，实测 0 命中），且 `T0000` 的候选落在与本类现有文件相隔 16.18 天的另一簇，因此可以构造一个"该类的文件级留出、且文件时间代理来自另一簇"的评测集。
- 但**只能表述为 `file-level held-out with a different file-time proxy`**，不能写成跨会话 / 独立采集会话。
- **两个必须先认下的限制：**
  1. **配置混杂**：`T0000` 的新日期候选同时是 `switched_band`（S11000–S11111），而现有 8 个是 `initial_comm_band`。三类中**没有任何一个新日期候选在 D 与 S 两个轴上都与现有文件对齐**，所以它带来的是"新日期 + 新频段组"的双重变化，不能当作单因素留出。

### 9.3 哪些类仍缺跨批次代理？

- **本任务只获准筛查 `T0000`/`T0010`/`T0101` 的 88 个成员**。其余 10 个已选类（`T0001`、`T0011`、`T0100`、`T0110`、`T0111`、`T1000`、`T1001`、`T1010`、`T1011`、`T1100`）的未下载成员**本次一个都没读**，所以对它们**没有任何新证据**，仍然全部缺跨批次代理。
