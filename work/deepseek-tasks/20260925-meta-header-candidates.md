# META-HEADER1：旧三类未下载候选的归档头时间筛查

Codex 已验收 `work/meta_split1/META-SPLIT-1-report.md` 的数字与可行性判断，但收紧术语：MAT `Created on` 与 RAR HTIME 都是文件时间，RAR 可能继承源文件修改时间，两者匹配不是两个独立采集日志；只能当文件时间/批次代理，不证明实际无线电采集会话。现有 104 文件每类仅一个短时间簇，不能冻结 13 类跨批次或全新未参与选型的 final test。

本任务获准只读取官方冻结归档里旧三类 T0000、T0010、T0101 尚未下载的 88 个成员的**RAR 文件块头**，不下载压缩载荷，不写 G/F，不训练、不生成正式 split。依据 `work/meta_split1/archive_unused_for_legacy3_20260925.csv` 和 `work/sel12g/sel12g-config-20260924.json` 的归档身份（URL、大小 615955805466、ETag `"6774350c-8f69d3b51a"`）与冻结索引。每个成员先请求从 block_offset 起的足够短前缀以解出 RAR5 header-size vint，再仅请求到 header_end 为止；严格不读取 header_end 之后的载荷字节。单成员头部总长度上限 128 字节；若超过或解析不符，记录异常，不扩大读取。预计总传输远小于 100 KiB（计入重复前缀），不可切换成整包或成员载荷下载。

对每次 HTTP Range 验证 206、准确 Content-Range/总长、ETag；对每个头验证 RAR 块头 CRC、file 类型、冻结文件名和 packed_size，并用**事先固定**的 HTIME flags/时间制式解析规则生成 `file_mtime_proxy`。先在已有的 14 个本地成员头上锁定并记录解码规则；不可为了让候选落入期望日期而逐个调整时区/格式。对 HTTP 429 使用有界退避，仍失败则保留错误并报告，勿发起大量重试。

在 `work/meta_header1/` 输出逐候选 CSV/JSON（文件名、类、距离/段代码、packed/unpacked 字节、头部 CRC/姓名核验、原始时间字段、解析后的文件时间、HTTP 请求数/下载字节/错误），按类与日期汇总可供选择的文件及预估完整下载量。明确回答：旧三类是否各有与现有 104 文件不同的文件日期候选；候选是否可能支持未参与选型的文件级测试；哪些类仍缺跨批次代理。绝不将不同文件日期直接写成“独立采集会话”或承诺 13 类跨会话最终测试。

如端点身份改变、索引不匹配、无法在 128 字节内安全解析，停止并报告 needs_codex。结束时写工作流交接。不得修改正式 G 清单、MAT、旧 `.part` 或当前分组草案；旧三类候选的完整载荷下载须待 Codex 另行决定。
